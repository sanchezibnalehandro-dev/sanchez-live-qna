# SANCHEZ LIVE Q&A — реестр мероприятий и сценариев

Обновлено: **2026-10-25 (МСК)**. Тип: **карта конфигураций и статусов**, не протокол проверки всех публичных страниц и не инструкция по изменению live-состояния.

## 1. Граница продукта

**Один производственный продукт:** `sanchez-live-qna` (GitHub `main`), основной frontend `https://qna.sanchez-ai.ru` на Timeweb, резервный frontend `https://sanchez-live-qna.vercel.app`, **один существующий** Supabase `BLACK_Q_A` (`xofydbxnficxmiyncygq`). Разные темы, мероприятия и специальные страницы — **не отдельные копии приложения**.

- `speaker` и `panel` — режимы **комнаты** Q&A, не отдельные приложения.
- `event_key` объединяет комнаты одного Q&A-события; `slug` обозначает конкретную комнату. Отдельная комната может иметь `event_key = null`.
- Program v2 — существующий ограниченный событийный слой Q&A, не разрешение на разработку универсальной event-платформы.
- Audience Choice для ELINA — **специальная механика голосования**, использующая две дополнительные таблицы в том же Supabase; она не заменяет голосование за Q&A-вопросы и не создаёт второй Q&A-продукт.
- Оформление выбирается маршрутом в `brand.js` и стилями `brands/`. INNOSTAGE использует самостоятельный HTML-макет, а не preset Q&A.
- Флаги текущей сессии, открытого приёма и статуса опроса изменяемы; их читают **в Supabase в момент работы**, не из этого реестра.

**Критическая граница INNOSTAGE:** вечер **29 октября НЕ является ещё одной Q&A-комнатой**. Для него не создавался отдельный `qna_rooms` и не подтверждён Q&A `event_key`. Страница `innostage.html` не является `welcome.html?event=...` и **не имеет потока вопросов, голосования за вопросы или окна модератора**. Scramble — внешняя по отношению к этому репозиторию игра, ссылка на неё находится на странице. Не придумывать `event_key=innostage-...` и не направлять туда гостевые Q&A-ссылки.

**Не смешивать даты:** стендовые активности INNOSTAGE на KDW **30 октября** и закрытый вечер INNOSTAGE **29 октября** — разные организационные сценарии. В этом реестре выделена именно гостевая страница вечера. Наличие стендовых выступлений **не означает**, что под них создана дополнительная Q&A-комната или самостоятельное приложение.

**Комнаты TASIGO:** `tasigo-esg-plenary`, `tasigo-esg-business`, `tasigo-esg-game`, `tasigo-esg-hoteliers` (все `panel`). Это **четыре сессии одного события**, а не четыре версии приложения.

**Технический ключ `elina-28-rehearsal`** встречается в оформлении и отдельном репетиционном опросе (`draft` на момент проверки), но **полноценное Q&A-событие/комната под этим ключом в `qna_rooms` не подтверждены**. Не выдавать этот ключ за дополнительное готовое мероприятие.

## 4. Непостоянное состояние: датированная проверка 25.10.2026

Ниже результат чтения **production Supabase** при составлении реестра. Это **не предписание менять флаги**:

- Базовый SANCHEZ: приём вопросов закрыт.
- TASIGO: текущая `tasigo-esg-game`, приём вопросов открыт, **несмотря на прошедшую дату**. Не маркировать базу как архивированную без отдельного действия оператора.
- ELINA: Q&A `elina-28-session` не текущая, приём закрыт; основной Audience Choice `closed`, репетиционный `draft`. Датированная запись 18.10 о `OPEN` **уже не соответствует базе**.
- KDW / Финохин: комната текущая, приём вопросов открыт; это может быть подготовка/тест, а не начало мероприятия.
- INNOSTAGE: Q&A-флагов нет, поскольку это статическая страница, а не room/event.

Текущий блок **Program v2** и текущая **Q&A-сессия** — разные сущности. У ELINA может быть выбран `service`-блок программы при нуле текущих Q&A-комнат. Переключение программы/текущей Q&A-сессии допускается только явным операторским действием; выбор комнаты для редактирования не активирует эфир.

## 5. Где проверять факты и что не смешивать

1. **Текущий код, оформление и маршрут:** GitHub `main`, прежде всего `brand.js`, `brands/`, `welcome.html`, `ask.html`, `program.html`, `participants.html`, `innostage.html`.
2. **Фактические комнаты, программа, переключатели и опросы:** production Supabase `xofydbxnficxmiyncygq`; технические SQL-снимки `schema.sql` / `RLS-auth-next.sql` сверять с production при DB-задачах.
3. **Фактически размещённый frontend:** Timeweb для канонического `qna.sanchez-ai.ru`; Vercel — резерв. Состояние Timeweb не выводить только из GitHub `main`.
4. **Программа, имена, время, постановка:** согласованные файлы и сообщения организатора конкретного мероприятия. БД может содержать тестовое расписание.
5. **Принятые архитектурные ограничения:** `ARCHITECTURE_DECISIONS`, `LIVE_EVENT_MODEL`, `SUPABASE_RUNTIME_CONTRACT` и инструкции ChatGPT Project. Датированные `PROJECT_STATE` и release notes — снимки, не live-статусы.
6. **ELINA Audience Choice:** `docs/decisions/2026-10-18-audience-choice-no-self-vote.md`; **запрет самоголосования** действует. Старые MASTER и PDF с разрешённым самоголосованием — только архив.

Этот файл — **одна карта**, а не второй MASTER каждого мероприятия. Его дополняют только при появлении подтверждённого мероприятия, другой конфигурации или изменении границы сценария; ежедневные флаги не превращают в постоянные инструкции.

## 6. Непроверенное перед мероприятиями

- **ELINA 28:** окончательные названия команд/публичное время; физический прогон iPhone + Android; скан QR и действия оператора на основном Timeweb; намеренный текущий статус основного опроса.
- **KDW 30:** фактический guest/moderator/admin прогон; окончательный брендинг и сценарная готовность Финохина.
- **INNOSTAGE 29:** окончательная программа вместо заглушки; доступность `/innostage.html` и переходов Scramble/Telegram с гостевого телефона.
- **Общее:** технический контроль Timeweb после релизов и повышение существующего Supabase до Pro перед ожидаемой большой нагрузкой по ранее принятому решению.

Создание реестра **не меняет** параметры live, содержимое БД, даты, названия программ и ссылки на внешние приложения.
